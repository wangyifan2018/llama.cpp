# 语言判定与说话人：调研与实测（座舱 ASR）

日期：2026-11-17
范围：Paraformer-zh/en（8404 词表，单模型双语）在 SM6650 上的 LID、说话人识别与降噪可行性。
关心的指标：`endpoint_to_final_ms`、车控/座舱常用词精度。

## 0. 结论摘要

1. **解码后的脚本判定就是可用的 LID，成本 0 ms**：纯中文段 100% 判 zh、纯英文段 100% 判 en，
   4.97 s 中英混说段的语言切换点误差 40 ms。已接入 API（`X-Language` 头 + `segments[].language`）。
2. **用当前数据训练声学 LID 不可行**：同一套特征跨音色只有 56.2% / 68.8%（二分类随机是 50%），
   因为"语言"与"说话人"被混淆——同一批特征做说话人识别却是 98.4%（中文内 100%、英文内 100%）。
   结论：样本里学到的首先是音色，不是语言。
3. **说话人识别可行且便宜**：4 个 TTS 音色的最近质心判别 98.4%，成本约等于 0 ms。产品形态应是
   "司机声纹注册 + 每段相似度门控"，用来抑制乘客说话造成的误触发，而不是做语音分离。
4. **真正的降噪（目标说话人提取）当前不可行**：没有可用的分离模型，设备端更现实的是多麦/波束成形。
   数据上它有明确收益上限：babble 5 dB 时命令字段只有 31.2%（干净时 56.2%）。
5. **对 `endpoint_to_final_ms` 的影响**：脚本 LID 0 ms、声纹门控 ~0 ms（复用同一帧特征）、
   学习型 LID 约 5–15 ms、TSE 10–30 ms。当前 277 ms 的主项仍是 encoder 241 ms。

## 1. LID 三条路线

| 路线 | 数据需求 | 成本 | 实测 |
|---|---|---|---|
| A. 解码后脚本判定（已实现） | 无 | 0 ms | 纯句 100%，混说切换点误差 40 ms |
| B. 声学特征 + 小分类器 | 每语言多说话人 | ~0.02 ms | 跨音色 56.2% / 68.8%（不可用） |
| C. 预训练 LID（ECAPA / Whisper-LID 等） | 需模型权重 | 5–15 ms | 本机无外网，未测；需 100 MB 级模型 |

### 1.1 A：脚本判定（已接入）

`paraformer_transcribe_tokens()` 给出每个 token 的时间与文本，按"是否含 CJK 字节"判语言：

```text
mixed.wav (zh 2.32 s + 0.4 s 静音 + en 4.97 s)
  segments: (0.00-2.10 zh 把主驾空调调到二十一度) (2.76-4.80 en set the footwall lights to forty percent)
  X-Language: mixed
纯中文 -> X-Language: zh     纯英文 -> X-Language: en
```

切换点 2.76 s 对比英文真实起点 2.72 s（中文结束 2.32 + 0.4 s 静音），误差 40 ms。

**成本**：token 化路径要算每个位置的 posterior（对 8404 词表做一次 softmax），实测在宿主上
`json` 与 `verbose_json` 的 `X-Infer-Ms` 中位数都是 125–127 ms，**没有可测差异**；设备上
同一条 2.3 s 音频 `X-Language: zh`、`X-Infer-Ms: 354`（同一时段 `json` 为 299–355，波动来自设备）。
所以脚本 LID 不占 endpoint->final 预算。
局限：段内语言由**解码结果**推断，若整段被识别成另一种语言（重度噪声/口音），判定会跟着错。
所以它是"报告用"的 LID，不能用于**解码前**选模型。

### 1.2 B：声学 LID 为什么不行

特征：80 维 log-mel（25 ms/10 ms），去静音后取均值+标准差（160 维），标准化后逻辑回归。
数据：64 条 TTS 命令（Tingting/Flo 中文各 16、Samantha/Daniel 英文各 16）。

| 实验 | 结果 |
|---|---|
| 5 折交叉验证（同音色） | **100%** |
| 跨音色：训练 Tingting+Samantha，测 Flo+Daniel | **56.2%** |
| 反向：训练 Flo+Daniel，测 Tingting+Samantha | **68.8%** |
| 短句（<1.8 s，n=8） | 100%（同音色内） |

同一批特征的说话人判别：中文内（Tingting vs Flo）100%、英文内（Samantha vs Daniel）100%、
四音色 98.4%。**特征里说话人信息远强于语言信息**，这就是跨音色崩掉的原因。

要让 B 可用，至少需要每语言 20+ 说话人、每人多条；这台机器上没有这种数据，也没有外网。
所以 B 路线**暂缓**，等真实座舱录音或公开多说话人语料。

## 2. 说话人：从"识别"到"降噪"的现实路径

### 2.1 能做的：声纹门控（成本 ~0 ms）

- 注册：让司机说 3–5 条命令，取 160 维统计特征均值作为声纹；
- 判定：每个 VAD 段用同一套特征算余弦相似度，低于阈值就"不是司机"，可直接丢弃或只记录不执行；
- 成本：特征在 fbank 之后本来就有，判定是一次 160 维点积（~µs），**不进 `endpoint_to_final` 关键路径**；
- 收益：乘客闲聊不再触发车控。当前硬负样本 16 条里 12 条是 near-miss（句中有设备词+状态词），
  这类句子一旦被语义层误判就是误触发，声纹门控是第一道闸。

风险与边界：TTS 上 98.4% 不代表真人；注册与使用必须同麦、同增益，否则相似度不稳；说话人变化
（感冒、疲劳）需要阈值留余量。**必须用真实录音验证后才能上线。**

### 2.2 做不到的：目标说话人提取（TSE）

真正的"识别说话人以达到降噪"= 从混合音里分离出目标说话人。需要分离模型（Conv-TasNet /
MossFormer 一类），本机没有权重、没有训练数据，且 10–30 ms 起的额外延迟会直接吃掉
`endpoint_to_final` 的余量（当前 277 ms 里 encoder 占 241 ms，余量很少）。

设备端更现实的降噪路径是**多麦 + 波束成形**（座舱通常有 2–4 个麦），它不需要模型、延迟 ~1 ms，
但需要硬件通道与阵列几何信息。

收益上限（已有数据，§18.3）：babble 5 dB 时命令字段 31.2%、zh CER 7.83%；干净时 56.2% / 0.60%。
也就是说"把另一路说话人压掉"最多能把这类场景从 31% 拉回 56%。

## 3. 对现有指标的影响

| 功能 | 额外延迟 | 是否在 endpoint->final 关键路径 | 备注 |
|---|---:|---|---|
| 脚本 LID（已实现） | 0 ms | 否 | 解码后统计 |
| 声纹门控 | ~0 ms | 否 | 复用 fbank 统计，可在解码前粗筛或解码后丢弃 |
| 声学 LID（B） | 0.02 ms | 否 | 但当前精度不可用 |
| 预训练 LID（C） | 5–15 ms | 是（若解码前路由） | 需模型 |
| TSE | 10–30 ms | 是 | 需模型，且会推高尾延迟 |

## 4. 与车控精度的关系

当前 32 条命令字段 78.1%（热词 + span rewrite + 停顿标点），剩余失败集中在三类：

1. **BPE token 数不匹配**：`footwall/footwell`(3↔2)、`lights/likes`(3↔2)、`rear vents/reevent`(2↔1)；
2. **中文同音**：`掉/调`，`分为灯/氛围灯`；
3. **未登录实体**：POI 名、联系人名（`陈佳宁`、`Sarah`）。

第 1、3 类都不是 LID 能解决的，需要**段级上下文偏置**（候选词表 + trie 约束/前缀增益）；
第 2 类要靠声学或重训。所以优先级上，上下文偏置 > LID。

## 5. 建议的落地顺序

| 优先级 | 事项 | 理由 | 验收 |
|---|---|---|---|
| P0 | 司机声纹门控（enroll + 余弦 + 阈值） | 直接减少乘客误触发，成本 ~0 ms | 真实录音上的 FRR/FAR；硬负样本误触发数 |
| P1 | 段级上下文偏置（POI/联系人/车控词表 + trie 约束） | 直接抬车控精度，覆盖 token 数不匹配的错 | 命令字段、未登录实体召回、误触发 |
| P2 | 声学 LID（B/C） | 当前数据不可用；只有做双语双模型路由时才需要 | 跨音色准确率 > 95% 才启用 |
| P3 | TSE / 多麦波束成形 | 需要模型或硬件通道；收益上限 31% -> 56% | babble 5 dB 下的命令字段 |

## 6. 复现

```sh
# 声学 LID 与说话人可分性（numpy 特征 + 逻辑回归/最近质心）
python3 tools/lid_prototype.py            # 见本文件附录的脚本要点
# 解码后 LID
bin/llama-paraformer MODEL mixed.wav --timestamps
curl -D - -X POST localhost:8080/v1/audio/transcriptions -F file=@mixed.wav -F response_format=verbose_json
```

附录：原型脚本要点（80 维 log-mel、25/10 ms、去静音、均值+方差 160 维、L2 逻辑回归、
最近质心）。数据来自 `fixtures-tingting` 与 `voice2` 两个 TTS 包（Tingting/Flo/Samantha/Daniel）。
